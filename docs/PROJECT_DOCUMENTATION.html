🔐 1. Authentication Module APIs

POST /api/auth/login
Description
Authenticates an agency operator, agent, or administrator using email and password credentials, returning a signed JWT Bearer token and assigned role.
Work & Data Flow
1. Sanitizes and normalizes the input email to lowercase.
2. Queries auth.users (or fallback users table) for user record.
3. Verifies plaintext password against the stored bcrypt hash using bcrypt.checkpw().
4. Parses user metadata to determine authorized role (admin, agency, agent).
5. Generates a signed HS256 JWT access token containing subject ID, email, role, and expiration timestamp (default 24h).
6. Returns { access_token, role, email }.
Security Posture & Mitigations (Resolved)
  • ✅ Credential Brute-Forcing & Stuffing Mitigated: Enforced IP/account sliding-window rate limiting on POST /api/auth/login. Blocks automated password guessing after 5 failed attempts within 60 seconds with an HTTP 429 Too Many Requests response and Retry-After: 60 header. History is cleared immediately upon successful login.
  • ✅ User Enumeration Prevented: Replaced divergent errors ("email is wrong" vs "your password is wrong") with a unified constant error: "Invalid email or password" (HTTP 401). Includes dummy bcrypt execution on non-existent accounts to eliminate side-channel timing analysis.
  • ✅ Weak Secret Key Production Guard Enforced: Backend startup in main.py automatically aborts (os._exit(1)) if APP_ENV=production and a default/weak key (e.g. "change_this_to_random_secret_key", "secret", or < 32 chars) is detected in .env.
POST /api/auth/register-outlook
Description
Self-registers a new agency user via an Outlook/Office 365 workflow, creates the agency record, and returns an active session token.
Work & Data Flow
1. Validates that the email does not already exist in auth.users or users.
2. Hashes the provided password using bcrypt.hashpw() with a cryptographically secure salt.
3. Inserts credentials into auth.users with metadata role agency.
4. Creates a corresponding record in the agencies table linked to the user's UUID.
5. Signs and issues a JWT token immediately so the agency user is logged in automatically.
Bugs, Edge Cases & Cyber Threats
  • Threat — Unrestricted Public Registration: Open registration without email verification or domain whitelisting allows unauthorized external users to create agency records. Mitigation: Require email confirmation tokens before activating agency status.
  • Bug/Edge Case — Orphaned Records on Partial Failure: If user insertion succeeds but agency insertion fails, a rollback occurs, but error handling across dual-table schemas requires strict transaction atomic locks.
GET /api/auth/me
Description
Validates the caller's JWT Bearer token and returns the current user profile (ID, email, and role).
Work & Data Flow
1. Extracts the token from Authorization: Bearer <token> header.
2. Decodes and verifies token signature and expiration against SECRET_KEY.
3. Returns UserProfile(id, email, role).
Bugs, Edge Cases & Cyber Threats
  • Threat — Revocation Invalidation (Stale Tokens): Because JWTs are stateless, if an administrator deletes or disables a user, their token remains valid until expiry. Mitigation: Maintain a token blocklist in Redis or verify user active flag in database on sensitive operations.
POST /api/auth/logout
Description
Logs out the user and signals the frontend client to clear local session tokens.
Work & Data Flow
1. Verifies caller authentication.
2. Returns success message {"message": "Successfully logged out"}. Frontend removes localStorage token.
Bugs, Edge Cases & Cyber Threats
  • Threat — Client-Side Only Cleanup: Since backend does not maintain a server-side session store, an intercepted token can be reused until its natural expiry.

👥 2. Customer Management APIs

GET /api/customers/
Description
Lists all customers belonging to the agency with complete field metadata.
Work & Data Flow
1. Verifies Bearer authentication.
2. Queries customers table via SQLAlchemy repository ordered by creation date.
3. Serializes records using CustomerSchema (79+ columns) and returns JSON array.
Bugs, Edge Cases & Cyber Threats
  • Threat — Broken Object-Level Authorization (BOLA / IDOR): Ensure query filters strictly by the authenticated agency's agency_id so Agent A cannot view Customer data belonging to Agency B. Mitigation: Enforce tenant isolation in repository queries.
  • Threat — Denial of Service via Large Result Sets: Fetching all rows without database-level LIMIT / OFFSET pagination can cause high memory usage when customer records exceed 50,000+. Mitigation: Implement server-side pagination with TanStack table.
POST /api/customers/
Description
Creates a brand new customer profile with 79+ fields, including service groups, contacts, and loss history.
Work & Data Flow
1. Pydantic validates input payload structure against CustomerCreate schema.
2. Normalizes phone numbers, postal codes, and EIN formats.
3. Inserts record into customers table via SQLAlchemy repository.
4. Commits transaction and returns created customer with generated ID (HTTP 201).
Bugs, Edge Cases & Cyber Threats
  • Threat — SQL Injection: Mitigated via SQLAlchemy parameterized queries. Ensure no raw string interpolation is ever added.
  • Edge Case — Duplicate Customer Records: Simultaneous submits can create duplicate accounts with the same Tax ID or business name. Mitigation: Add unique constraint on (agency_id, tax_id).
GET /api/customers/{customer_id}
Description
Retrieves the complete customer dossier by primary key ID.
Work & Data Flow
1. Looks up customer by customer_id in database.
2. If not found, raises HTTPException(404, "Customer not found").
3. Returns serialized customer schema.
Bugs, Edge Cases & Cyber Threats
  • Threat — IDOR (Insecure Direct Object Reference): Any authenticated user guessing integer IDs could inspect other agencies' customers. Mitigation: Add filter(Customer.agency_id == current_user.agency_id).
PUT /api/customers/{customer_id}
Description
Updates an existing customer profile with partial or complete fields.
Work & Data Flow
1. Verifies customer exists; raises 404 if missing.
2. Filters out unset attributes via model_dump(exclude_unset=True).
3. Updates customer entity and commits changes. Returns updated model.
Bugs, Edge Cases & Cyber Threats
  • Threat — Mass Assignment: Protect sensitive internal flags (such as account agency ID or billing balance) from being modified by untrusted client payloads.
DELETE /api/customers/{customer_id}
Description
Deletes a customer and cascades deletion to associated records (policies, notes, certificates).
Work & Data Flow
1. Verifies customer existence.
2. Deletes customer row in DB (foreign key cascading removes policies and documents).
3. Returns HTTP 204 No Content.
Bugs, Edge Cases & Cyber Threats
  • Threat — Accidental Data Loss: Hard deletions remove customer records permanently. Mitigation: Implement Soft Deletes (is_deleted = True) with audit trail logs.
  • Threat — Unauthorized Deletion by Agents: Restrict deletion permission to users with admin or agency roles.

🛡️ 3. Policy & Coverage Management APIs

GET /api/customers/{id}/policies
Description
Lists all insurance policies (General Liability, Auto, Umbrella, Workers Comp) for a specific customer.
Work & Data Flow
Queries policies table filtering by customer_id. Returns array of policy schemas with status, effective date, expiration date, and company name.
Bugs, Edge Cases & Cyber Threats
  • Edge Case: Expired policies should be clearly flagged with status Expired vs active policies to prevent invalid certificates from being distributed.
PUT /api/customers/{id}/policies/{policy_id}/general-liability
Description
Replaces or updates General Liability rating limits (Each Occurrence, Fire Damage, Med Exp, Personal & Adv Injury, General Aggregate, Products/Completed Ops).
Work & Data Flow
Deletes existing coverage records for the policy and atomically re-inserts the updated array of coverages and dollar limits inside a database transaction.
Bugs, Edge Cases & Cyber Threats
  • Bug / Race Condition: Concurrent edits by two agents can overwrite each other's coverage updates. Mitigation: Add optimistic locking using a version number or updated timestamp.
GET /api/customers/{id}/policies/{policy_id}/workers-comp/part2
Description
Fetches Workers' Compensation Part 2 Employers Liability coverage limits.
Work & Data Flow
Queries workers_comp_part2 for eachAccidentLimit, diseaseEachEmployee, and diseasePolicyLimit. Returns HTTP 204 if no record exists yet.
Bugs, Edge Cases & Cyber Threats
  • Edge Case: When returning HTTP 204 (No Content), clients must handle empty responses cleanly without attempting to parse JSON.

📦 4. Documents & Cloud Storage APIs

POST /api/customers/{customer_id}/documents
Description
Uploads a policy document or endorsement attachment, stores it in Backblaze B2, and registers document metadata in the database.
Work & Data Flow
1. Receives multipart form data (file, action, description, refNum).
2. Reads binary stream and uploads file asynchronously via a threadpool worker to Backblaze B2 bucket.
3. Creates database record in customer_documents with B2 file ID, secure URL, and author.
4. Returns serialized document metadata.
Bugs, Edge Cases & Cyber Threats
  • Threat — Malicious File Upload (Remote Code Execution): Uploading executable files (.exe, .sh, .php, .html with XSS scripts). Mitigation: Enforce strict file extension and MIME type whitelisting (PDF, PNG, JPG, DOCX only) and sanitize file names.
  • Threat — Storage Exhaustion / Large Payload DoS: Uploading multi-gigabyte files. Mitigation: Enforce max upload file size (e.g., 25MB limit in FastAPI middleware).
GET /api/customers/{customer_id}/documents/{doc_id}/download
Description
Streams a stored document back to the client or generates a short-lived authorized download token for B2.
Work & Data Flow
1. Verifies document ownership under customer.
2. If stored in Backblaze B2, requests a scoped download authorization valid for 24 hours.
3. Proxies the file stream with correct Content-Disposition: inline and Content-Type headers to eliminate browser CORS blocks.
Bugs, Edge Cases & Cyber Threats
  • Threat — SSRF (Server-Side Request Forgery): The download endpoint streams content from the URL stored in the DB. If an attacker injects an internal URL (e.g. http://169.254.169.254/latest/meta-data), the server could leak cloud credentials. Mitigation: Whitelist permitted domain prefixes (e.g., only Backblaze B2 endpoints).

📜 5. Certificates & Certificate Holders APIs

GET /api/customers/{customer_id}/certificates
Description
Retrieves all Master Certificates created for a customer to populate the eForms navigation tree.
Work & Data Flow
Queries certificate_masters for the customer, including form data JSON and row selections. Returns list of master schemas.
Bugs, Edge Cases & Cyber Threats
  • Edge Case — Corrupted Form Data JSON: Ensure schema handles malformed or legacy JSON strings in form_data gracefully without raising unhandled 500 exceptions.
POST /api/customers/{customer_id}/certificates/{certificate_id}/holders
Description
Creates a new Certificate Holder under a master certificate with custom operations description and endorsement provisions.
Work & Data Flow
1. Verifies parent master certificate exists.
2. Stores holder name, address, city, state, zip, desc_of_ops, written notice days, and JSON flags for Additional Insured and Waiver of Subrogation.
3. Returns created holder record (HTTP 201).
Bugs, Edge Cases & Cyber Threats
  • Threat — XSS Injection in Certificate Holder Data: Malicious input in Holder Name or Description of Operations rendered inside PDF HTML templates. Mitigation: HTML-escape all user-provided strings before rendering in browser templates.

👑 6. Administrator Module APIs

GET /api/admin/stats
Description
Calculates platform-wide metrics (total customers, total agents, total agencies, database status).
Work & Data Flow
Protected by require_role(["admin"]). Executes count queries across customers and parses auth.users roles to return aggregate system counts.
Bugs, Edge Cases & Cyber Threats
  • Threat — Privilege Escalation: Endpoints with admin dependency must verify the role strictly from verified JWT claims rather than client-supplied query parameters or headers.
PUT /api/admin/users/{user_id}/role
Description
Elevates or demotes a user's role (e.g. promoting an agent to agency operator or administrator).
Work & Data Flow
Updates the role key inside auth.users.raw_user_meta_data for the target user ID. Commits changes to Supabase Auth.
Bugs, Edge Cases & Cyber Threats
  • Threat — Self-Lockout / Orphaned Admin: An admin could accidentally demote their own account, leaving the agency with zero administrators. Mitigation: Disallow self-demotion or ensure at least one active admin remains.

🏢 7. Agency Operational APIs

GET /api/agency/reports
Description
Generates agency business analytics: customer breakdown by status, Commercial vs Personal accounts, and top 5 geographic states.
Work & Data Flow
Executes SQL aggregation query on customers using COUNT and conditional SUM expressions. Formats distribution maps and returns JSON analytics payload.
Bugs, Edge Cases & Cyber Threats
  • Threat: Ensure agency filter is applied in multi-tenant environments so agencies only see analytics for their own books of business.

⚡ 8. eForms & High-Fidelity PDF Engine

POST /api/eforms/{id}/override
Description
Persists inline interactive edits made on the ACORD 25 viewer (edited text fields, changed checkbox states, custom limits).
Work & Data Flow
Saves JSON dictionary of field ID overrides linked to the master certificate ID and logs the author's email for revision audit tracking.
Integrity & Overrides Persistence (Resolved)
  • ✅ High-Fidelity Override Persistence Resolved: Overrides saved via /api/eforms/{id}/override are now automatically fetched and injected into both master and holder nodes during PDF generation in print-options, email-options, and eForms manager preview. Re-generating or re-printing certificates reproduces exact user-customized field values without requiring manual re-entry.
