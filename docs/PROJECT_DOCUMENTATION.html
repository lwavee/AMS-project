Sterling AMS 360 — Insurance Management Platform

A modern, comprehensive Insurance Agency Management System (AMS) built with Next.js 15, FastAPI, PostgreSQL/Supabase, and an advanced ACORD 25 Certificate Engine with native vector PDF generation.

Version: 2.4.0-Production
Target Industry: Property & Casualty Insurance
Last Documented: September 2026

🌟 1. Project Executive Summary

Sterling AMS is a full-featured, enterprise-grade cloud agency management solution engineered for independent commercial and personal lines insurance brokerages. It unifies customer relationship management (CRM), policy administration across four primary commercial lines, hierarchical certificate management (eForms Manager), and pixel-perfect document rendering.

🏢 Multi-Role Security
Fine-grained RBAC separating Agency Operators, Account Managers, Producers, and Platform Administrators with JWT auth.
📜 ACORD 25 Standard
Automated generation and inline interactive editing of industry-standard Certificate of Liability Insurance forms.
🌳 eForms Tree Manager
Hierarchical master-to-holder tracking, document attachments, certificate copying, and multi-recipient email distribution.
⚡ High-Fidelity PDF Engine
Native browser SVG foreignObject vector compilation (via html-to-image + jsPDF + pdf-lib) eliminating font-shift errors.

📐 3. System Architecture

The platform enforces a strict unidirectional decoupled architecture. The frontend defines the functional requirements and acts as the source of truth for all user interactions, while the FastAPI backend provides domain-driven modules. 

[ Browser Client / Next.js 15 App ]
   │
   ├── eForms Manager (Tree Browser: Masters -> Holders -> Docs)
   ├── Interactive ACORD 25 View / Inline Overrides
   └── Print & Email Pipeline (html-to-image -> jsPDF -> pdf-lib)
         │
         │ REST API calls (Bearer JWT Tokens)
         ▼
[ FastAPI Backend / Python 3.11 ]
   │
   ├── api/v1/router.py (Route Aggregator)
   ├── modules/customer/  (CRUD, 79+ profile fields)
   ├── modules/policy/    (GL, Business Auto, Umbrella, Workers Comp)
   ├── modules/eforms/    (Certificates, Holders, Document Attachments)
   └── modules/auth/      (JWT validation & Role-Based Access Control)
         │
         ▼
[ PostgreSQL / Supabase Database ]
   ├── customers, customer_policies
   ├── certificate_masters, certificate_holders
   ├── policy_gl_coverages, policy_ba_coverages, policy_wc_part2
   └── customer_documents (Attachments & uploads)

👥 4. Customer Center & Profiles

The customer profile system models real-world commercial brokerage data with over 79 discrete fields. Customer records support both Commercial and Personal lines classifications.

Key Profile Sections

  • Basic & Contact Info: Customer name, DBA, address, city, state, zip, phone, primary email, website, tax ID / EIN.
  • Classification: Type (Commercial, Personal, Life/Health), Status (Active, Prospect, Inactive), Source, Account Exec.
  • Dynamic Nested Collections:
    • Service Groups: Dedicated account servicing teams and branch assignments.
    • Contacts: Multiple customer contacts with direct dials, cell numbers, and email addresses.
    • Dependents / Locations: Subsidiary locations and covered entities.
    • Loss History: Historical claim logs with carrier notes, reserves, and amounts paid.

🛡️ 5. Commercial Policy Management

Policies are modeled with granular coverage limits directly tied to standard ACORD rating schedules:

Commercial General Liability (CGL)
Tracks Each Occurrence ($1M), Damage to Rented Premises ($50k), Medical Expense ($5k), Personal & Adv Injury ($1M), General Aggregate ($2M), and Products/Completed Ops ($2M).
Business Automobile (BAP)
Tracks Combined Single Limit (CSL), Bodily Injury per Person/Accident, Property Damage, and vehicle coverage symbols (Any Auto, Owned, Scheduled, Hired, Non-Owned).
Commercial Umbrella / Excess
Tracks Occurrence and Aggregate excess liability limits above underlying General Liability and Auto policies.
Workers' Compensation & Employers Liability
Tracks Part 1 Statutory limits and Part 2 Employers Liability: Each Accident, Disease - Each Employee, and Disease - Policy Limit.

📁 6. eForms Manager & Certificates

The eForms Manager (located at /agency/customer/[id]/eforms-manager) is a replica of the industry standard AMS360 eForms suite.

Core Capabilities:

  • Master-Holder Hierarchy: Create master certificates representing overall coverage. Attach unlimited Certificate Holders (contractors, lenders, landlords) with customized descriptions of operations and written notice days.
  • Interactive ACORD 25 Preview: View the certificate exactly as it appears in print. Toggle Edit Mode to modify individual fields or toggle checkboxes (Claims-Made vs Occur, Additional Insured, Subrogation Waived).
  • Document Attachment Management: Upload additional endorsements (e.g., CG 20 10, CG 24 04) directly under any Master or Holder node.
  • Distribution Workflows:
    • Print Forms: Select any combination of masters, holders, and attachments to merge into a single download or separate PDF packages.
    • Email Forms: Select holders, auto-populate email templates, attach generated certificates, and send directly via agency SMTP.

📄 7. PDF Generation & Print Pipeline

To ensure certificates print with 100% legal precision, Sterling AMS uses a dual-layer rendering system:

Native SVG Vector Rendering: By replacing legacy html2canvas text measurement with html-to-image, the browser's native Blink engine rasterizes fonts and table borders via SVG <foreignObject>. This completely eliminates vertical font drift, overlapping cell borders, and missing table lines.

Generation Process Flow:

  1. An invisible viewport-aligned iframe loads the ACORD template with active policy parameters.
  2. Dynamic CSS overrides enforce clean table separation (border-collapse: separate; border-spacing: 0;) and vertical alignment.
  3. html-to-image rasterizes the rendered .page element at pixelRatio: 2 (High DPI 300+ print resolution).
  4. jsPDF converts the vector canvas image into a clean Letter-sized PDF page.
  5. pdf-lib concatenates the certificate with any attached endorsement PDFs into the final unified file.

🔌 8. REST API Specification

Method Endpoint Description
POST /api/auth/login Authenticate user and return JWT bearer token.
GET /api/customers/ Retrieve paginated list of agency customers with search & filter.
POST /api/customers/ Create a new customer profile with 79+ supported fields.
GET /api/customers/{id} Retrieve detailed customer profile by ID.
PUT /api/customers/{id} Update customer details, nested contacts, and servicing groups.
GET /api/customers/{id}/policies List all active and historical policies for customer.
GET /api/customers/{id}/certificates List certificate masters for customer.
POST /api/customers/{id}/certificates Create a new certificate master.
GET /api/customers/{id}/certificates/{certId}/holders List certificate holders under a specific certificate master.
POST /api/customers/{id}/certificates/{certId}/holders Add a certificate holder with AI/WOS endorsement flags.
GET /api/customers/{id}/documents List uploaded documents and attachments.

🚀 9. Setup & Development Guide

Prerequisites

  • Node.js 18+ (Node 20+ recommended)
  • Python 3.11+ and pip
  • PostgreSQL or Supabase project URL

1. Frontend Setup

cd frontend
npm install
npm run dev
# Application starts at http://localhost:3000

2. Backend Setup

cd backend
python -m venv venv
# On Windows:
.\venv\Scripts\activate
# On Linux/macOS:
source venv/bin/activate

pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
# API docs available at http://localhost:8000/docs

3. Environment Variables (frontend/.env.local)

NEXT_PUBLIC_API_URL=http://localhost:8000
NEXT_PUBLIC_APP_NAME="Sterling AMS"

4. Environment Variables (backend/.env)

DATABASE_URL=postgresql://user:password@localhost:5432/ams_db
SECRET_KEY=your_production_secret_key_here
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_KEY=your_supabase_anon_key
